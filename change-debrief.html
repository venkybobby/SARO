STORY-CHUB-011 — Validation-Status Filtering for Rule-Pack Data

Change debrief · story 3/8 · P0 SummitCare demo-blocker · stacked on story/STORY-RPV-002

1. Context

The 2026-07-04 radar scan flagged 28 DRAFT_UNVALIDATED and 7 RETIRED rule rows — and nothing filtered them, so unvalidated/retired regulatory mappings were being presented to customers as authoritative. CHUB-011 adds a server-side visibility filter so default customer views show only SME-validated (and provisionally-visible legacy) content. Internal auditor personas can opt into seeing drafts, badged. This is a leak-prevention control aligned with the anti-overclaiming posture.

2. Intuition + key discovery

get_matrix_rows is the single aggregation point feeding all three customer surfaces — the row list, the coverage counts, and the CSV export. Filtering there once closes every leak surface (including the "easiest leak", export) in one place. governance_rules isn't served to customers, NIST has no status column, and the eval path already pins to published snapshots (RPV-002) — so the blast radius is exactly the EU-rule rows in the matrix.

The filter is fail-closed: visibility is an allow-list (status IN (SME, LEGACY?)), and SQL IN excludes NULL for free — a future insert that bypasses the column default can't sneak in.

5. Understanding check

Why filter inside get_matrix_rows instead of in each endpoint?
It's the one function all three customer surfaces (list, coverage-counts, CSV export) call. Filtering there means a new surface built on it inherits the control automatically, and the "easiest leak" (export) can't forget to apply it. One chokepoint = no divergence.
A row's validation_status is NULL. Visible by default? Why?
No — hidden. Visibility is an allow-list (SME, optionally LEGACY); NULL isn't in it, and SQL/`in` semantics exclude it. This is fail-closed: a row that bypassed the column default (which is LEGACY) still can't appear as authoritative content.
Why does the CSV export not offer the draft toggle even to an ai_auditor?
An exported CSV is a portable artifact that can travel outside the tool to non-privileged eyes. The authoritative exported matrix should contain only validated content; drafts are for interactive internal review only. So export is always default-filtered — the conservative, leak-safe choice the story emphasizes.
Where does AC-5 (draft rows excluded from evaluation) get satisfied, if not here?
By RPV-002: GRC checks resolve against a static crosswalk, and evaluations pin to PUBLISHED snapshots whose publish gate already excludes DRAFT/RETIRED. Snapshot membership supersedes this UI filter for the eval path — so no evaluation code is touched by CHUB-011.
